# Support Policy

This document declares the supported release streams, support end dates, security vulnerability reporting channels, and end-of-life and backport policies for `riboseinc/cla` in accordance with EU Cyber Resilience Act (CRA) Article 14.

## Supported Release Streams

| Release Stream | Tag Pattern | Status | Support Until |
| --- | --- | --- | --- |
| `0.1.x` | `v0.1.*` | Supported | `2029-11-23` |

The `0.1.x` release stream is actively maintained until `2029-11-23`. This support-until date matches the `support-until` value (`2029-11-23`) configured in `.github/workflows/release.yml` and stamped into the `lifecycle.json` asset of each published release.

Development occurs on the `main` branch, and tagged releases on `0.1.x` carry SBOMs, build provenance attestations, and lifecycle metadata generated by the release workflow.

## Security Vulnerability Reporting

Do not open public GitHub issues or pull requests for undisclosed security vulnerabilities.

Report suspected security vulnerabilities through GitHub Private Vulnerability Reporting at <https://github.com/riboseinc/cla/security/advisories/new>. You may also contact the Ribose security team via <security@ribose.com>.

Published vulnerability advisories, package statuses, and OSV/GHSA feeds for Ribose software are available at <https://cve.ribose.com>. Confirmed vulnerabilities in supported release streams are coordinated, patched, and published through GitHub Security Advisories and <https://cve.ribose.com>.

## Backport Policy

Security fixes and critical defect fixes are backported from `main` to all actively supported release streams. New features and non-critical enhancements are delivered on `main` and included in subsequent minor or major release streams rather than backported to older streams.

When a security fix is released for a supported stream, a new patch tag is published with updated SBOMs, SLSA build provenance attestations, and `lifecycle.json` metadata.

## End-of-Life Policy

Once a release stream reaches its declared `support-until` date, that stream enters end-of-life. End-of-life release streams do not receive security patches, bug fixes, backports, or new release artifacts.

Users running an end-of-life release stream must upgrade to an actively supported release stream to continue receiving security updates and maintenance. Any extension or revision to a declared support period is published in an updated version of this document and reflected in `.github/workflows/release.yml` for subsequent releases.
